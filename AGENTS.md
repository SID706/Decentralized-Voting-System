# AGENTS.md

Decentralized Voting dApp (React + Solidity). Development stack lives in
`docker-compose.base44.yml`; there is no separate backend — the "database" is a
local Hardhat chain.

## Run

```shell
docker compose -f docker-compose.base44.yml up -d
```

Services:

| service  | role |
| -------- | ---- |
| `install`| one-shot `scripts/ensure-deps.sh`; skips `npm ci` unless package.json/package-lock.json changed |
| `chain`  | `npx hardhat node` on `chain:8545` (replaces Ganache from the README) |
| `deploy` | one-shot `scripts/deploy.js`, writes `public/deployment.json` |
| `web`    | `react-scripts start` on host port 3000 |

## Non-obvious details

- The repo as imported contained no `src/`, `public/`, `contracts/` or
  `scripts/` (only empty `code` / `start.txt` placeholders), so the React app,
  the `Voting` contract and the deploy script here were reconstructed from the
  README's description.
- The browser never talks to the chain directly: JSON-RPC goes to `/rpc` and
  `src/setupProxy.js` forwards it to `RPC_TARGET` (`http://chain:8545`). This
  keeps the app same-origin and avoids CORS.
- `public/deployment.json` is generated by the deploy service and gitignored.
  If the chain is recreated without re-running `deploy`, the app shows
  "The contract has not been deployed yet". Fix with
  `docker compose -f docker-compose.base44.yml up -d --force-recreate chain deploy web`.
- `hardhat.config.js` reads `RPC_URL` (default `http://127.0.0.1:8545`) for its
  `localhost` network so the deploy container can reach the `chain` service.
- `REACT_APP_DEV_PRIVATE_KEY` is Hardhat development account #0, a publicly
  documented key valid only on the local chain. It lets the UI vote without the
  MetaMask extension (MetaMask is used automatically when the browser injects
  `window.ethereum`). Never point this app at a real network with that key.
- No external credentials are required for this stack. The README's Volta
  testnet deployment (`API_URL` / `PRIVATE_KEY`) is optional and unused here.
- `scripts/ensure-deps.sh` runs `npm ci` only when the manifest/lockfile hash
  changed. A bare `npm ci` on every stack start deletes `node_modules` under the
  already-running dev server and breaks its webpack build — that is why the
  install service is guarded.
- Every `docker compose up -d` re-runs the `deploy` service, so a restart gives
  a fresh contract (new address in `public/deployment.json`) with an empty
  ballot. Expected in dev; not lost data.
- Chain state is in-memory: restarting `chain` resets votes and requires a
  re-deploy.

## Verify

```shell
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:3000/            # 200
curl -s -X POST http://localhost:3000/rpc -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"eth_chainId","params":[]}'         # 0x7a69
docker compose -f docker-compose.base44.yml ps                             # chain/deploy done, web healthy
```
